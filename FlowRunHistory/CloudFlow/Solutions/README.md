## Import and configure

1. In the intended tenant/environment, open **Solutions > Import solution** and
   choose the appropriate ZIP. Use the ordinary solution import workflow.
2. Map the two connection references to authorized **same-target-tenant** connections.
   The HTTP reference is **HTTP with Microsoft Entra ID (preauthorized)**, not
   HTTP v2 or a custom OAuth connector. Create a dedicated connection if needed:

   | Connection setting | Public | Standard GCC |
   | --- | --- | --- |
   | Base Resource URL | `https://api.flow.microsoft.com` | `https://gov.api.flow.microsoft.us` |
   | Microsoft Entra ID Resource URI | `https://service.flow.microsoft.com/` | `https://gov.service.flow.microsoft.us/` |
   | Identity authority | Public Entra ID | Public Entra ID, **not AzureUSGovernment identity** |

   Map **SharePoint reports** to the connection authorized to create/read files
   at your approved report site. Existing unrelated connections are not modified.
3. Enter the ordinary **solution environment-variable values** at import, or open
   those definitions in the imported solution and set **Current value** afterward:

   | Setting | Required value |
   | --- | --- |
   | Target tenant ID | The target Entra tenant GUID owning the mapped connections. Report context only; it cannot switch OAuth tenants. |
   | Report SharePoint site URL | Approved HTTPS site URL without a trailing slash, for example `https://YOUR-TENANT.sharepoint.com/sites/Reports`. |
   | Report folder path | An **existing** site-relative library/folder path, default `/Shared Documents/FlowRunHistory`, without a trailing slash. |

   Tenant/site have no shipped default or current value. No source-site value is
   transported. Public schemas start `fhr_Public`; GCC schemas start `fhr_GCC`.
4. The packaged collector is **Off/Draft by default** (`StateCode=0`,
   `StatusCode=1`). If an import option offers to enable flows, leave it off until
   configuration and connection mappings are reviewed. Open/save the collector,
   then **Turn on**. A later environment-variable edit requires save or off/on
   refresh before the flow uses the new value.
5. Run the collector manually from the solution. Start with **one flow/run and
   Summary**, select JSON/CSV/Both, and inspect its completed status and report
   coverage. `CallingRecordId` plus `IdOnly=true` writes only verified ID strings.

There is **zero explicit Secure Inputs/Outputs configuration** in either package.
As requested, raw action inputs/outputs, payloads and signed content links can be
visible to authorized owners/co-owners in run history. Users may add supported
Secure Inputs/Outputs settings themselves. OAuth, required `SecureObject` types,
Embedded bindings, same-cloud HTTPS guards, anonymous signed-content downloads
without bearer forwarding, and report credential/link withholding remain enabled.
Changing I/O visibility does not reveal or bypass protected historical source data.

## Contents and validation

Each package contains exactly **one stopped collector, two unbound connection
references, and three Text environment-variable definitions**. It contains no
test drivers, fixture data, current variable values, actual connection IDs, demo
tenant/site/workflow IDs, credentials, or captured histories. The `.settings.example.json`
siblings are optional, empty mappings generated by PAC; portal users do not need
to edit or use them.

Both exact ZIPs were built with installed **PAC 2.10.1 SolutionPackager** from
sanitized metadata derived from a genuine Dataverse unmanaged export, then
PAC-unpacked/repacked/unpacked and checked for equivalent native content.
Dataverse **StageSolution** passed for both exact byte streams with no missing
dependencies or solution-validation errors. Staging is **not import, connection
binding, activation or a GCC runtime test**.
